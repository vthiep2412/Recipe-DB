## Problem Statement
Standard recipe apps fail in real kitchens because they treat cooking as a flat, single-threaded wall of text. Cooking is a physical process with distinct components, shared cookware, sensory doneness checkpoints, and advance prep requirements. Existing apps clutter grocery lists, surprise cooks with sudden hours-long chilling steps mid-recipe, and force unnecessary dishwashing.

## What Makes This Cool
1. **Component-Based Architecture:** Recipes are organized by natural maker-defined pieces (for example in Tiramisu: "Coffee Dip", "Mascarpone Cream", "Layering", "Chill & Set") rather than an arbitrary flat list.
2. **Advance Pre-Prep Heads-Up:** Avoids the classic 6:30 PM dinner trap. An upfront card flags any advance lead time (like "soften butter 30m" or "marinate 2 hours") before you start cooking, without being a rigid gatekeeper.
3. **Creator-Authored Timer Notes & Sensory Cues:** Cooking times are ranges, not rigid deadlines. Timers carry direct notes from the recipe maker (for example: "Bake 20 to 25 mins, watch closely after 20m until edges are deep golden"). When the chime rings, it tells you what sensory cues to look for, locked strictly to maker specifications with simple pause and resume controls.
4. **Self-Sufficient Prose (Wet Hands Usability):** Steps are 100 percent readable in plain language without forcing the cook to tap nested popups with flour-covered hands (for example: "Dip ladyfingers into the prepared coffee dip in Bowl A"). Interactive tokens highlight source steps as a helpful visual reference, never a required obstacle.
5. **Vessel-Yield Binding and Re-Use:** Steps track vessels (`Bowl A`, `Bowl B`, `Skillet`) with explicit reuse directives (for example: "Pour egg whites from Bowl B into Bowl A" or "Wipe skillet and reuse for sauce"). Intermediate yields explicitly know which vessel currently holds them.
6. **Mobile Audio Alarm & Wake Lock:** Background timers use timestamp delta math (`Date.now() - startTime`) so phone sleep never throttles the countdown. Audio chimes are unlocked on initial tap, and `visibilitychange` listeners re-acquire the Screen Wake Lock (`navigator.wakeLock`) so alarms actually ring when your phone is in your pocket.
7. **Creator-Controlled Step Numbering:** Each step has an `isCountedStep` flag. Steps with `true` get numbered (1, 2, 3), while setup notes and reminders stay as clean unnumbered callouts.

## Constraints
- Stack must remain Preact, Vite, TypeScript, and Bun.
- Zero external dependencies introduced without explicit approval.
- Zero forced external API calls on standard recipes.
- No artificial time limits or forced countdowns on human actions.
- Step prose must remain readable on its own without requiring token interaction.
- All styles must respect dark and light themes, responsive layouts, and accessible keyboard navigation.

## Core Data Contracts (TypeScript Specification)

```typescript
export interface RecipeGraph {
  schemaVersion: 1;
  id: string;
  title: string;
  servings: number;
  description?: string;
  leadTimeSummary?: string; // e.g. "Advance prep: soften butter 30m"
  inputs: RecipeInput[];
  vessels: RecipeVessel[];
  components: RecipeComponent[];
  meta?: Record<string, unknown>;
}

export interface RecipeInput {
  id: string;
  name: string;
  amount: number;
  unit: string;
  prepState?: string; // e.g. "softened", "cold", "finely minced"
  leadTimeSec?: number; // e.g. 1800 for 30m tempering
  notes?: string;
}

export interface RecipeVessel {
  id: string;
  name: string;
  type: 'bowl' | 'pan' | 'pot' | 'baking_dish' | 'tool';
  capacity?: string; // e.g. "large, min 3 qt"
  dimensions?: string; // e.g. "9x13 inch"
}

export interface RecipeComponent {
  id: string;
  name: string;
  steps: RecipeStepNode[];
}

export interface RecipeStepNode {
  id: string;
  componentId: string;
  isCountedStep: boolean;
  instructionText: string; // Fully readable standalone prose
  tokens: RecipeToken[];
  vessels?: {
    vesselId: string;
    role: 'primary' | 'source' | 'destination';
    actionAfter?: 'holding_yield' | 'empty' | 'needs_wash' | 'wipe_clean';
  }[];
  consumesYields?: { yieldId: string; partition?: string }[];
  producesYield?: {
    id: string;
    name: string;
    vesselId: string; // Vessel holding this yield
    description?: string;
  };
  timer?: StepTimer;
  meta?: Record<string, unknown>;
}

export interface StepTimer {
  id: string;
  label: string;
  minSec: number;
  maxSec?: number; // Supports ranges like 20-25m
  creatorNote?: string; // Direct guidance from the maker
  donenessCue?: {
    type: 'visual' | 'tactile' | 'temperature' | 'aroma';
    description: string; // e.g. "Deep golden, toothpick comes out clean"
    targetTemp?: { value: number; unit: 'C' | 'F' };
  };
}

export type RecipeToken =
  | { type: 'text'; text: string }
  | { type: 'ingredient'; inputId: string; displayText: string; amount?: number; unit?: string }
  | { type: 'cookware'; vesselId: string; displayText: string }
  | { type: 'yield'; yieldId: string; sourceStepId: string; displayText: string; partition?: string }
  | { type: 'timer'; timerId: string; displayText: string };
```

## Mobile and Kitchen Usability Architecture
1. **Advance Prep Alert:**
   - Evaluates `leadTimeSec` across all inputs before cooking begins.
   - Surfaces an upfront non-blocking advisory: *"Advance Prep: Soften mascarpone and butter 30 minutes before starting."*
2. **Timer Runner with Sensory Doneness:**
   - State: `{ startTime: number, targetDurationMs: number, isPaused: boolean, remainingMs: number }`.
   - Tick logic reconciles via `Date.now() - startTime`.
   - Expiration dialog displays the maker's sensory doneness cue and creator note, with pause, resume, and dismiss controls locked to maker specifications.
   - Web Audio element unlocked on user interaction; `visibilitychange` re-acquires `navigator.wakeLock.request('screen')`.
3. **Wet Hands Prose Guarantee:**
   - `instructionText` is always complete and natural English without requiring token interaction.
   - Tokens overlay subtle visual highlights and tooltips without breaking text readability.
4. **Vessel State Flow:**
   - Steps clearly indicate which bowl or pan is occupied and when it can be wiped or washed.
